# Stage 3 — Chat implementation contract

Build real-time live chat on the existing Stage 2 backend. No deploy, simulated chat, permanent history, controls, agent directives, SDK, export, or uploads in this stage. Use the existing stack and a room-scoped Durable Object with WebSocket Hibernation. Keep static links and snippets inert; no raw HTML or server URL fetching.

## Slices

1. Add `GET /api/rooms/:id/ws`, route upgrades to the existing room DO, and authenticate a versioned `join` frame before welcome or membership data. Reuse the existing session and membership checks; never put a credential in a URL. Use the existing origin policy for browser connections; allow an absent Origin for native clients only with valid authentication, never allow an explicitly disallowed Origin. Permit cleartext only on loopback. Attach server-validated identity to the socket for hibernation, never the raw bearer token; cap unauthenticated connections and make them expire. Close or filter expired and revoked connections at the authorization boundary, including outgoing fan-out. Add tests before implementation.
2. Add server-authored v1 chat events and live fan-out to authorized connections in one room. Validate the type, field shape and UTF-8 size (at most 32 KiB); validate reply and mention targets in the same room, never trust client-supplied sender, timestamp or room, and enforce authorization and per-participant rate limits server-side. Observers may read but not send. Use bounded short-lived reply metadata if needed; do not promise reconnect history before Stage 6.
3. Implement real presence, counting multiple connections per participant, and rate-limited ephemeral typing. Add browser integration: connect and rejoin using the in-memory session, show live timeline and presence, send and reply, mentions by participant ID, code as plain text, clear connection/error states. Do not silently retry sends or retain secrets in persistent browser storage.
4. Verify browser-to-backend real-time chat in GitHub Actions. Cover bad origins, invalid/expired/revoked auth, room isolation, observer rejection, size and rate checks, close/leave/presence and multi-client delivery. Document the wire shapes and the live-only limitation. Record the exact verified commit and CI run in `docs/stage-3.md`, then advance the roadmap.
